## Beta 1.2.4: four bugs from the HR usability review (November 1, [PR 13](https://github.com/AzJester/Talent-Acquisition-Agent/pull/13))

A usability review of the beta found four bugs that saved a wrong record or showed a wrong score. All four are fixed. The fixes then went through two rounds of independent reviewers trying to break them, and what they found was fixed too.

**1. Do-not-target list.** Typing "Acme Corp" used to say "Saved 0 entries." and save nothing, so the company was never blocked.
- Plain company names now save, one per line. Pastes from Word, Excel, CSV and numbered or bulleted lists are cleaned up.
- The YAML form is checked strictly. Any mistake is refused with the line or field at fault, and nothing is saved.
- The saved list shows as a table, and the edit box shows plain names, so adding a line keeps working.
- Matching ignores capitals, accents, apostrophes, punctuation, a leading "The" and legal endings. "Acme Corp." blocks "Acme Corp" and "The Boeing Company" blocks Boeing, but "Sierra Nevada Corporation" does not block Sierra Nevada Brewing Co.

**2. Review reasons.** Reject used to default to "Not senior enough", and one click recorded it.
- Both reason lists start on "Choose a reason". Approve and Reject stay off until one is picked.
- The next page confirms the decision and reason, with Undo. Undo will not overwrite a decision someone made after yours.
- A fast double click records one decision, not two.
- "Clear decision" on a candidate's page returns them to review, and can also be undone.
- The Approved count is recounted from storage, and notices are announced to screen readers.

**3. Sample sign-off.** "Try it with sample data" used to approve the Software Factory Lead template as "Sample data demo", and every later real search showed that approver.
- The sample now runs on its own demo copy, which is never signed off, cannot be edited, and never appears in New search.
- "Sample data demo" is refused as an approver name.
- Older beta browsers reuse their existing sample search.
- "Start a search" on a rubric page opens New search on that rubric.

**4. Keyword scoring.** Every keyword hit used to score 2 of 4. An active TS/SCI scored 2, and any keyword scorecard topped out at 50 of 100.
- Keywords can carry their own score. The template's clearance item now scores TS/SCI 4, Top Secret 3 and Secret 2, with the common spellings of TS/SCI.
- A plain keyword on an item that has nothing else to score it now counts as FOUND, full credit.
- A mention after "no", "not" or "without" is skipped.
- Inactive, expired, former and eligible-only clearances score at most 1 unless the words around them say active.
- Team size reads more ways people write it ("Leads 120 engineers", "(65 engineers)" after a leadership title), but not audiences, hires or company size.

**Scorecards approved before this release keep the scoring they were approved with.** A new scorecard or a new version uses the new rules. The browser and the Python app score identically: checked on 230 test profiles with no differences.

Keyword scoring is still approximate, because it reads words, not meaning. Score with Claude for nuance.

Testing: 53 Python tests (16 new), 69 browser checks for these fixes, and the 30-check regression run from the earlier review all pass.

## Beta 1.2.1: fixes from the end-to-end beta review (November 1, [PR 9](https://github.com/AzJester/Talent-Acquisition-Agent/pull/9))

A full review of the beta with the sample data confirmed 46 issue reports, which came down to 28 distinct problems. All were fixed. A 30-check browser run against the built site passes, and the test suite grew to 37 tests.

Problems that blocked or misled testers:

- Score with Claude sent one candidate instead of ten when the search page was reloaded or opened from the list (the Top box reset to 1).
- The do-not-target list showed as empty after a reload, and saving it then deleted the stored entries.
- A 500-row CSV kept the page busy for about 2 minutes 40 seconds. It now saves in under a second.
- A rejected API key said "Claude is not allowed for this app in your account". It now says the key was rejected and points to Governance.
- A file too large for browser storage left a half-saved search stuck in "saving". The partial search is now removed, with a message that gives the real capacity (about 1,900 candidates per browser).
- People Data Labs enrichment files (single or bulk) failed or produced unnamed candidates.
- An Experience, Work History or Resume column was dropped when the file had no job title or company column.

Accuracy and display:

- Totals now round exactly as the Python app does (Alex Brennan in the sample shows 21.2, not 21.3). A new test compares the two on about 38,000 values.
- Role matches show as dashed "Role" lines that point to the job in the Profile table, instead of a "Title | Company" string that appeared nowhere on the page. The template outreach draft now quotes a sentence from the profile.
- Export CSV puts each quote on its own line in its cell, writes role references as "Role: …", and stops spreadsheet formulas from running.
- A failed single scoring batch or a refused batch is reported, and a search is labeled Claude-scored only when at least one candidate was.
- Claude outreach failures stay visible under the button; dash cleanup no longer leaves stray spaces.
- Links to a deleted or unknown search, candidate or rubric show a "not here" page instead of "Loading" forever.
- Deleting a search removes its row at once and refreshes the audit log; leaving Governance cancels a pending delete.
- Status lines such as "Saved." no longer vanish; typing focus survives live updates; the API key field clears after Save key.
- Files with no recognized columns are refused with a message naming the expected columns.
- Try it with sample data reopens the existing sample search instead of making copies.
- Exclusion reasons no longer print a double period (fixed in the Python app too).
- Governance states the real browser capacity and how many candidates are stored.

Documents: the Help page, `docs/User_Guide.docx` and `docs/BUILD_NOTES.md` were updated to match, including new troubleshooting rows and a note that every site under `azjester.github.io` shares browser storage.

## Beta onboarding fixes (November 1, [PR 7](https://github.com/AzJester/Talent-Acquisition-Agent/pull/7))

The first beta tester could not get the app to work while following the user guide. The cause: the site loaded its YAML and CSV parsers from a public CDN that work networks often block, so Add as draft and file upload failed silently.

- The site now serves its own copies of the parsers and loads no third-party scripts.
- Try it with sample data: one click approves the template rubric and builds a finished search from the sample file.
- Unexpected errors appear as a notice at the top of the page; a startup check says plainly when the browser cannot run the app.
- Plain messages for Excel files and for Create search with no file chosen.
- The rubric approval box moved above the editor, with an Approve button in the header that jumps to it.
- Quick start and new troubleshooting rows in the Help page and user guide.

## Decisions made during the session

- No scraping of LinkedIn, Indeed or any other site. The tool scores only licensed exports and Astrion's own records.
- GitHub Pages is the only user-facing version. No claude.ai sign-in is asked of users.
- No AWS access for now; the AWS path stays documented in the build notes.
- No pilot; the app went straight to a team beta.
- Concept phase: access is open and sample data is fictional.
